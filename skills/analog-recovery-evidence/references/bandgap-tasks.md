# Bandgap 取证任务卡 v0.1

本卡只规定可复核的取证任务，不注入某个项目的电压、面积比、温度范围、器件命名或原作者意图。每个任务都必须引用输入包中的原始位置；没有证据时填写 `UNKNOWN`，不能用 bandgap 的常见数值补齐。

## 角色与已有技能对应

主编排按[角色卡](../../analog-recovery/references/role-cards.md)派任务；本卡不自行派代理。

下表的 VERIFIER 交接仅在准备夹具或实际运行时启用；纯静态任务由 ANALYST 与 REVIEWER 完成，不等待仿真角色。卡级 PASS/PARTIAL/BLOCKED 按主编排交接规则映射任务状态，不能当作产品指标通过。

| 任务 | owner / 借用能力 | 交给谁、检查什么 |
|---|---|---|
| BG-01 端口 | ANALYST / learn 路径追踪、audit 连接检查 | REVIEWER 独立核对端序/边界；VERIFIER 审真实端接 |
| BG-02 核心回路 | ANALYST / learn 等效关系；必要时 design 手算方法 | REVIEWER 检查符号链、方程条件与反例；VERIFIER 提供区分观测 |
| BG-03 偏置 | ANALYST / learn 器件组作用、audit 比例检查 | VERIFIER 测电流/余量；REVIEWER 核对共享节点与计量 |
| BG-04 启动/关闭 | ANALYST 提假设与夹具，VERIFIER 执行 | REVIEWER 区分静态解、上电、使能和关闭边界 |
| BG-05 性能 | VERIFIER / verify 与 Spectre | ANALYST 解释冲突；REVIEWER 核对有效域和极值；EDITOR 只消费已验收结果 |

存在上层连接时由 ARCHITECT 用 integrate 的方法核对，不能把集成分析作为所有局部任务的前置条件。背景原理只选读 learn 对应部分；audit 清单逐项核对适用性，不读取全部技能或把历史经验值作为当前指标。

## 共同输入与输出

静态任务的输入包必须冻结以下内容：

1. 已准入的原始网表及其哈希；顶层定义、候选 DUT 根实例和端口顺序。
2. 模型/section/corner 的来源和适用范围；若没有模型，只做静态任务并标明限制。
3. 用户规格或供电来源。没有规格时可以登记诊断条件，但不能称为 nominal 或产品通过。

需要运行的任务再单独加入夹具和原始运行材料：生产测量包的每个 `raw_samples[].source` 必须有相对包目录的 `path` 与 `sha256`，每个运行必须有 `log_path` 与 `sha256`。静态端口/回路任务不因缺少 PSF 或日志而阻断，应该把运行材料列为后续 `next_step`。

每张卡输出一个独立 JSON 对象，至少包含：`task_id`、`status`（`PASS`/`PARTIAL`/`BLOCKED`）、`evidence_refs`、`observations`、`competing_explanations`、`next_step`、`confidence` 和 `uncertainty`。`DIRECT` 只用于原始连接、原始参数和原始类型；电流方向、功能极性、启动作用和环路解释至少是 `INFERRED`，除非有独立运行证据。

运行证据必须通过 `scripts/check_measurements.py` 的测量门禁：原始 PSF 类型决定单位，电流不能直接标成瓦特；功率必须由电压与电流按公式生成。供电条件必须记录来源和 `nominal`/`diagnostic` 作用域；gmin 影响或 bad pivot 的运行只能作为诊断或排除，不能标为 `qualified`。

执行者可先生成契约骨架：

```powershell
python skills/analog-recovery-evidence/scripts/check_measurements.py --example > measurement_packet.json
python skills/analog-recovery-evidence/scripts/check_measurements.py --synthetic measurement_packet.json
```

这个命令明确是 fixture 自检，不是生产证据。生产运行必须先把 `replace with ...` 替换为实际来源，并为每个原始信号填写 `source.path`/`source.sha256`，为每个运行填写 `log_path`/`sha256`，然后省略 `--synthetic`：

```powershell
python skills/analog-recovery-evidence/scripts/check_measurements.py measurement_packet.json
```

生产模式从哈希文件读取实际 PSF 类型行，例如 `"I(VDDsrc:p)" "I" ...` 或 `"V(vdd)" "V" ...`，不信任手抄 `psf_sample`；哈希、路径、signal 或唯一类型行失败都会阻断。`measurements[].formula` 使用 `identity`、`mul` 或 `power`：门禁只检查量纲与输入闭包，不计算数值，也不替代原始值真实性复核。示例条件是 `diagnostic`，不能直接改名为 `nominal`。

## BG-01 端口角色与夹具边界

**输入**：顶层端口定义、每个端口的直接连接片段、夹具源/负载和端口电压电流观测。

**操作**：

1. 先按端口顺序建立全集，区分电源、地、偏置、参考、控制、输出和未知角色；不能从端口名或理想源类型推断角色。
2. 对每个疑似输出/双向/未知端口，沿一到两级器件端接追踪电流路径，登记“内部驱动→外部负载”“外部驱动→内部输入”和竞争解释。
3. 外部使用证据不是内部角色分析的前置条件。若器件端接支持角色，登记 INFERRED 角色及竞争解释，再设计能区分解释的诊断负载；产品端接仍单独保留 UNKNOWN。对无法判定的节点先观察。外露端口若同时向内部支路供电，应保留内部支路，不能像独立电流输出一样钳位或抽取标称电流。
4. 驱动/负载由电路作用选择：控制输入用电压激励；独立电流输出用明确电压合规的接收负载并观测电流；内部共享节点采用高阻观察或有依据的扰动。有限电流值不等于有限输出阻抗。登记实际元件、阻抗、允许端口电压和停止条件，不能只填写 finite_current 字符串。
5. 核对端口实际电压、电流和合规范围；发现超轨时保留为诊断现象并追查端接，不能以收敛替代有效性。
   选被动电阻负载前先估算 Vport≈Ibranch×R；电阻虽有限，若所需端口电压已高于供电/合规窗口，仍不是有效电流输出夹具。电流未知时从有明确作用的保守负载起步，读取实际V/I和输出器件余量，再决定是否扩大负载范围。报告保留该外部负载条件，不把诊断电流当产品保证值。

**验收**：接口 expected/observed 集合完全相等；每个端口有 `role_basis`；每个 driven 端口有 source 和 compliance；未知角色没有无约束理想驱动。失败时先补端口角色证据或改用观察/有限负载夹具。

## BG-02 核心回路与反馈方程

**输入**：BGAMP 或等价候选放大器的端口绑定、两输入端连接、BJT/二极管结候选、电阻和反馈节点。

**操作**：

1. 从两个放大器输入分别回溯到结、电阻、镜像和输出节点，逐级记录实际网名、器件实例和极性。
2. 对每一条推断写出成立条件（例如节点电压关系、反馈方向、支路电流关系），并列出至少一个能区分竞争解释的观测。
3. 检查是否存在可识别的 PTAT/CTAT 合成路径；若只看到候选连接，写成“候选”并保留未知项。
4. 查找结面积、并联份数、几何参数和镜像比例的原始证据。没有参数或语义来源时不得填写典型面积比，也不得用理想 bandgap 方程反推实际比例。
5. 单独分析环路符号：选一个输入节点的小扰动，逐级列出输入对支路电流、镜像负载、输出级、驱动管和反馈分压的变化方向。注明尾电流近似不变/器件工作区等条件，不能用 vn/vp 名称直接指定正负输入，也不能因没有 OP 就省略条件性分析。随后用 OP 核对工作区，用局部扰动或环路实验检验；静态负反馈解释不等于相位裕度或启动成功。
   把“扰动节点→支路电流↑/↓→下一节点↑/↓”逐级列出。复核者先独立推导再比较；相反结论必须记录分歧，不得一边标pass一边写相反符号。尤其区分PMOS栅压上升导致电流减小、镜像负载两侧电流变化的叠加，以及后续反相级的再反相。

**验收**：输出核心回路图或结构表、方程/条件表、直接证据与竞争解释。必须明确哪些是 `DIRECT`、哪些是 `INFERRED`；不能只写“不能恢复原始意图”。失败时先补局部连接和 OP 观测，避免直接进入性能结论。

## BG-03 偏置、镜像与参考支路

**输入**：偏置入口、镜像栅/基极绑定、输出支路、器件 `w/l/m/nf` 等原始参数及工作点信号。

**操作**：

1. 从基准支路追到每个镜像输出，分别记录源/漏（或端子）方向、器件状态和对应端口。
   将支路分成独立外部电流输出、内部负载的外露偏置节点、偏置输入/共享节点；每类给出连接依据。先核对同栅同源及级联结构，再比较 w/l/m/nf。不要按同名前缀给全部端口复制同一负载。
2. 将原始几何参数、模型语义和工作点有效比例分开登记；几何倍数不能自动等同于电流倍数。
3. 对外部偏置/监视端口选择接收负载或高阻观察，并记录源输出阻抗与电流合规范围。
4. 分别测量 DUT 供电电流、注入支路电流和各电源域功率；功率测量必须引用实际 `V` 和 `I` 类型样本。

**验收**：每个镜像输出都有去向和观测计划；供电/注入不重复计量；没有把端口名或几何参数单独当作功能证明。比例不确定时保留区间/未知项并说明需要的模型或 OP 证据。

## BG-04 启动与关闭态

**输入**：启动支路候选器件、enable/trim 控制链、供电源、瞬态夹具和关闭态定义来源。

**操作**：

1. 查找零电流候选状态和可能的启动注入路径，记录启动支路何时应退出以及退出证据。
2. 分开登记供电斜坡、固定供电使能翻转、模式切换三种实验；DC 初始化保持不能充当启动证据。
3. 对关闭态明确仍保持的供电、参考和偏置；分别计量残余 DUT 功耗与夹具功耗。
4. 对每个控制码列出实际影响节点和可观察信号，不能只按 `en`/`flag` 名称赋予功能。

**验收**：启动和 hold 有不同 `claim_scope`；关闭态边界有来源；启动未退出、零电流或源不合规均进入诊断/失败记录。缺少真实使用场景时标为 `UNKNOWN`，不要假设关闭等于断电。

## BG-05 性能与运行质量

**输入**：BG-01 至 BG-03 已明确的端口边界、供电来源、模型有效范围和计划矩阵；实际 PSF/日志在准备运行时加入。BG-04 启动任务可并行或后续补做，不是有效 OP 的前置通过条件。

**操作**：

1. 先执行边界清楚的有效 OP，再登记温度/供电/trim/必要控制矩阵；启动矩阵单独登记，可在 OP 后补做。每个 case 有唯一 ID、完整条件和预先定义的失败判据。
2. `typ` 只表示声明的典型条件；两个 corner 不得自称全 PVT 最坏。找不到失效点时报告测试边界。
3. 逐条解析日志中的模型错误、gmin 影响、bad pivot、超时和未收敛。任何 gmin 影响或 bad pivot 的结果只能作为诊断或排除，不能 `qualified`。`Trying homotopy=gmin` 只记录求解过程，不等价于最终 gmin 影响告警；结合最终收敛、实际 gmindc 与影响告警分别判断，保留求解敏感性说明。nodeset DC 仍不证明启动。
4. 将每个性能数字追溯到原始类型样本、公式、测量窗口、条件和运行 ID；手填表格不能覆盖自动推导结果。
5. 箱式温漂明确参考电压及完整已验收温区：`(Vmax−Vmin)/(abs(Vref_at_Tref)×(T_high−T_low))×10^6`。分母不是电压极值所在两点的温差；缺参考点不得用最近点冒充，零温区不可计算。按有效采样范围重算并披露缺点，不能跨不同负载/模式合并。公式测试必须导入实际生产计算函数，不能在测试里重写另一份公式自证正确。
6. PSF 电气值属于 SIMULATED，配置记录属于 DIRECT，极值/温漂及方向变换属于 DERIVED。电源电流保留原始支路端名与正负号，再按已定义计量面转换，不能用 abs 掩盖回灌或端接错误。

**验收**：性能表只包含有效运行，诊断结果单独标识；供电条件的 `nominal`/`diagnostic` 与结论作用域一致；未测、部分测量和不适用分别写原因、影响和下一步。规格缺失时交付能力边界和诊断观察，不输出产品合格结论。

## 交接检查

主流程在交接前核对：

- DUT 根实例数量与计划一致，原始导出包装没有意外重复实例。
- 接口集合、端口方向、端接策略和供电来源均有独立证据。
- 每个测量有原始 PSF 类型、物理量、单位、公式和排除项；电源域不混加。
- 运行状态和日志异常已分类；`qualified` 没有未处理的 gmin/bad pivot。
- 任务卡没有写入未经证据支持的电压、面积比、温度、镜像倍数或原作者意图。
# 交给有界分析任务的最小材料

端口角色、PNP结压或反馈符号任务必须同时给出作用域内原始连接、正式端口绑定，以及相关模型的端序/器件类型metadata；缺metadata先提取或请求，不以实例前缀或常见端序当已知事实。不需要模型卡全文。

将静态判断、夹具执行、原始数据复算拆成可独立验收的小任务。已生成夹具和PSF的复算成功只证明该后处理能力，不能宣称执行模型已能从未知电路自主选择正确夹具。保留首次答案及主代理修正，避免用修正后结果回填首次通过率。
