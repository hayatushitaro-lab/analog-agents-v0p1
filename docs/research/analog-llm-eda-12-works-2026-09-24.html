先看研究版图

这 12 项不是同一种“电路视觉模型”。它们覆盖了一个从图像到工程决策的链条，但每项只解决其中一段，而且数据集、评测集和可复现的软件原型不能混为一谈。

4 项：图像与网表

AMSNet、AMSnet 2.0、Masala-CHAI、Image2Net，研究器件/导线/交点的识别、拓扑恢复、数据构建与误差度量。

4 项：能力评测

AMSbench、CIRCUIT、MMCircuitEval、EEE-Bench，检验视觉理解、计算、解释、设计或跨任务推理。

4 项：检索、设计与表达

AnalogRetriever 做跨模态检索；AMSnet-KG 做知识图谱辅助设计；EEschematic 把网表画成可读图；AnalogMaster 串起全流程。

核心结论：这些成果适合给仓库增加评测、检索和原理图导入/展示能力；现阶段没有一项可以替代 analog-recovery 的固定 DUT 证据链，也不应让视觉模型猜出的连接直接成为仿真事实。

这里的“高”表示方法与工作流贴合，不代表外部模型/数据已经能直接安装。analog-agents 面向规格驱动的前向设计；analog-recovery 面向参数固定电路的取证和报告，不能把二者的目标混淆。

01AMSNet — 原理图与 SPICE 网表数据集自动识别器件和导线，把教科书电路转成 SPICE 拓扑。数据集图像 → 网表早期基线›

原理

工作流先用 YOLOv8 检测器件及朝向，再对二值图上的连通像素做扩展，将器件、导线和交点归组；最后根据器件方向恢复 MOS 等器件的端序并写 SPICE。早期版本假设导线是实线、交叉处没有结点就不相连；遇到无法判定的多器件连接会报例外交人工处理。论文报告器件检测准确率 97.1%、人工核验的网连接准确率 96.7%。

怎样使用

适合用作“原理图—网表”配对数据和抽取基线：先在少量代表图上评估器件类型、旋转、交点和端序，再用配对样本做检索或模型回归。不要把其自动生成 netlist 当成黄金真值；按原图逐端核对才可进入 SPICE。

对仓库的价值

analog-agents：把器件/功能/拓扑标签做成 librarian 的视觉检索索引；用网表作静态结构提示。analog-recovery：只能作为从图像生成候选输入的早期原型；接受候选前仍须解析层级、MOS 端序、端口投影和实际夹具。

资源状态与限制

项目仓库提供生成 notebook 和数据 ZIP，并标注 GPL-3.0；README 同时称数据还在清理。不同来源对规模报出 792 与 894 张图，后续 AMSnet 2.0 论文也沿用 792，而 AMSNet v2 / Image2Net 比较表报 894。应记录所用数据版本，不混报样本数。许可适用对象及教科书图像再利用范围需核对。

02AMSnet 2.0 — 抗噪导线分割与可编辑原理图从器件检测进阶到 wire mask、拓扑重建和 OpenAccess 输出。多模态数据U-NetOpenAccess›

原理

用 YOLO11 检测元件，用 U-Net 对“导线像素”做语义分割，再在交叉点执行拆分与合并，避免只靠 bounding box 或脆弱的手写规则；合成文字、矩形标注等噪声作数据增强。根据检测到的元件引脚位置和导线段关系生成 Spectre 网表，并可重建带位置数据的 OpenAccess 原理图。

规模与结果

论文报告 2,686 个电路，包含原理图、Spectre 网表、OA 图和器件/网段坐标。其 easy / medium / hard 测试集上的 netlist F1 分别为 90.19 / 84.17 / 80.39；测试切片共 200 张。相比早期规则法，对复杂交叉、噪声标注的处理更贴近实际图像。

怎样使用与仓库适配

适合作为可选的 recovery 图像适配器：分割并输出“器件—pin—net—坐标”图，标注不确定的 crossings，随后由现有静态解析器建立 IR / scope packet；任何 AI 分割漏线、误连都应保留为诊断并阻断证据冻结。对 forward design，可扩充带几何定位的电路案例库。不要把 paper 的 F1 直接解释为本项目任意扫描件上的正确率。

资源状态

官方项目页提供数据和 supplementary code 的入口，且明确展示标注平台、数据构建和模型评测；本次可访问页面没有解析出具体下载地址。项目网页本身标注 CC BY-SA 4.0，但这不自动说明每张源图或数据资产都按同一许可授权。

03Masala-CHAI — 自动构建 SPICE 网表语料视觉检测、线段提取、LLM 整理与仿真验证组合成数据生产线。7,500 张论文报告自动数据构建ngspice 验证›

原理

论文流程将专用 YOLOv8 元件检测、Deep Hough Transform 导线段识别、端点半径聚类（约 40 px）和 LLM 生成/整理 SPICE 结合；数据来自 10 本教材。作者用数据微调模型，再接入 AnalogCoder，报告 Pass@1 绝对提升 46%。这个结果是作者特定任务和设置下的报告，不是通用电路准确率。

项目的实用更新

截至本次查询，GitHub README 另列出 2026 年 5 月的 V2：检测审核 agent、连线追踪/网表生成 agent、Judge 检查元件完整性与 ngspice 结果，失败时最多两轮反馈。其单图命令示例为 python -m agents_v2.run --image <图像> --output <目录>。但 README 仍写 7,500 张清洗版数据“即将提供”；代码含外部模型/API 与 Hough 权重准备步骤。

对仓库的价值

analog-agents：多角色审核和仿真回馈可借鉴到 verifier 的候选网表检查。analog-recovery：仿真能抓 syntax、DC 失败或模型报错，却不能证明图像中原始连接恢复正确；仿真失败时绝不能为“让它通过”而修改固定 DUT。只从只读副本产出候选和日志。

开放与限制

论文授权为 CC BY 4.0；GitHub 首页没有清楚展示独立的数据许可或下载入口。教材材料存在来源权利，代码可见不等于 7,500 张图片都可自由再分发。

04Image2Net — 多画风识别、Netlist Edit Distance风格判断 + 多个视觉算法，目标是减少复杂扫描图的拓扑错误。数据与 benchmark混合 CV 流程拓扑距离›

原理

先识别图的绘制风格，再按风格解释器件、交点、跨线/jumper 和端口；用视觉检测、线段跟踪与后处理逐步拼成异构电路图。NED 将 graph edit distance 按器件、网和端口数量归一化，让不同名称但同一拓扑的网表仍可比较。官方数据涵盖器件、方向/镜像、交叉点和网表真值四类。

规模与结果

论文报告 2,914 张完整图、48,930 个器件；网表评测含 104 个手工核验配对。作者报告成功率 80.77%。需谨慎引用 NED：论文摘要及对比表为 0.116，而正文另处出现约 0.657–0.659，指标报告存在不一致；实施时应锁定论文版本、验证集和具体表格口径。

怎样使用与仓库适配

官方 GitHub 是数据集/benchmark 仓库，包含验证工具，但明确不是完整 Image2Net 转换引擎。当前最有用的资产是“多画风困难样本”和 NED 评估思路。可为 analog-agents/recovery 自建回归集，把错连、漏连、pin 朝向错误作为图编辑类别；不要把 NED 低等同于器件型号、W/L、层级或模式正确。

许可

GitHub 仓库标注 Apache-2.0；数据来源含论文、教材、互联网等，README 要求同时遵守原始材料权利和适用数据许可。arXiv 论文页自身的 CC BY-NC-ND 标记不能与代码仓库许可混为一谈。

05AnalogRetriever — 图像、描述和 SPICE 网表跨模态检索把原理图、自然语言和端口感知电路图映射到同一检索空间。跨模态 RAG拓扑图编码ICCAD 2026›

原理

原理图由 CLIP/ViT 编码、自然语言由 Transformer 编码、网表由端口感知 RGCN 编码，三者通过三模态对比学习进入共享向量空间；分阶段训练，再引入 hard-negative 区分“拓扑相似但功能不同”的电路。因而可做 image↔text、image↔netlist、text↔netlist 六向检索。论文报告六向平均 Recall@1 为 75.2%，并将检索结果用于 AnalogCoder RAG。

实际可用资源与使用方式

Hugging Face 数据卡在 2026-09-23 更新，发布 6,371 组三模态样本，可下载用于构建检索原型；按卡片命令固定 dataset revision，运行发布校验器后再整理 CSV。其切分按样本 ID 随机，不保证来源或拓扑互斥，留出集还参与权重选择，因此不应称为完全独立的最终测试集。卡片报告 6,369/6,371 可编译、6,354/6,371 DC 通过；这仍不证明网表忠于图像或满足设计规格。

对仓库的价值

12 项里它与现有 librarian / analog-wiki 最贴近：查询可以从电路文字、图像或网表开始，返回候选案例。接入时只检索同工艺、同模块、具备来源与测量条件的案例；候选展示“为什么命中”和差异，不能直接改 DUT 或把历史数字写成新电路规格。

发布与数据权利

论文已获 ICCAD 2026 接收，但会议尚未举行；数据卡明确写源码与复现说明当时尚未公开，预计会议后开放。数据标为 masala-chai-derived，原理图及电路材料保留原有权利；代码的 MIT 不会重新授权数据。论文摘要所称 100% compile 与数据卡 99.97% 属四舍五入/发布快照口径，实际发布卡片给出精确计数。

06AMSbench — 感知、分析、设计综合评测把“看懂图、推断功能、算指标、写电路和 testbench”拆开测。约 8,000 题模型回归模拟 / 混合信号›

原理

分为 perception、analysis、design：感知拆成器件计数/分类/连线和网表；分析有图像问答与文字知识/计算；设计包括电路方案、仿真 testbench 和改错任务。作者对 8 个 MLLM 评测，重点指出复杂多模态推理和设计任务仍弱。GitHub README 将数据分为三类与难度；设计类只 68 题，题型覆盖规格到 testbench。

怎样使用

从当前最常用的岗位选子集：architect 测规格分解和 testbench，designer 测电路解释/设计反馈，verifier 测拓扑问答、计算和“看图找错”，recovery analyst 测功能/模式/指标解释。按任务、难度、图像输入分别统计；保留失败回答和逐题来源，避免把 benchmark 总分当签核。

适配价值和资源现状

提供 Hugging Face 数据和 GitHub 评测代码，适合补一套 agent 回归，而不是训练数据直接灌入所有技能。需留意 Hugging Face 页面当前显示 161 个顶层 JSON 记录、497 MB，且标注“No dataset card yet”；论文/README 报告约 8,000 题。应先检查行内封装的题目结构、图像分割和答案 schema，再决定统计分母。可访问页面没有显式数据许可字段。

07CIRCUIT — 电路解释与数值推理 benchmark用同一拓扑的多组参数形成“单题答对”与“整题组稳健”的区别。510 QA102 个模板单元测试式 pass@k/n›

原理

510 个问题覆盖模拟电路概念、拓扑和数值题；102 个题目模板各带 5 组数值参数。很多样本同时提供电路图、简化网表和题目上下文。除普通总体 accuracy 外，模板级 pass@k/n 要求在同一电路题组的多组数值条件中达到指定正确数，更像测试“是否理解这一拓扑”而不是碰巧算中一次。

结果与用法

论文报告 GPT-4o 最终数值答案准确率 48.04%，但严格 5/5 模板通过率约 27.45%；人工复核发现约 5% 自动评分是假阳性。可借用于 agent 评测：把同电路的变模式、负载/参数变化组成一个任务组，并同时评分数值与理由。对 recovery，要新增结合 SCS/模式控制/仿真日志的工程题；不能用教材 QA 代替电气证据。

08MMCircuitEval — 覆盖 EDA 多阶段的多模态题集一般知识、规格、前端、后端问题按领域与认知能力标注。3,614 题模拟 / 数字各半开源评测入口›

原理

把题目按设计阶段、analog/digital、text-only/multimodal、难度、题型以及 knowledge/comprehension/reasoning/computation 标记。3,614 题中一般知识 604、规格 490、前端 1,516、后端 1,004；总量模拟与数字各半，41.6% 为多模态，66.2% 是开放式题目。问题来自教材、题库、数据手册和工程资料，作者称经专家复核。

怎样使用

GitHub 示例：安装 Hugging Face datasets 后加载 charlie314159/MMCircuitEval，选 general/spec/frontend/backend 子集；配置待测模型后运行 evaluation/scripts/run_benchmark.py <field>。在 analog-agents 中先跑 analog 子集，按能力标签汇总，而不是让一个 judge 自行决定是否正确。

对 recovery 的扩展

可建立专用的结构化输出子集：每个回答引用当前证据包里的 claim ID、运行 ID、条件和单位。开放式问题另做工程师 rubric；benchmark 原始答案不能代替电气复核。当前 HF 页面没有显式 license 字段，GitHub 根目录也未显示独立许可证文件；论文 CC BY 4.0 不应自动视作数据/源图授权。

09EEE-Bench — 跨电气电子工程的图像推理评测通用 EEE 工程题，覆盖电路但不只面向模拟 IC。2,860 题10 个领域视觉“偷懒”诊断›

原理

评测高分辨率、上下文丰富的工程图与文字问题组合，要求图像理解 + 多步推理/计算，并优先选择可确定评分的答案形式。领域横跨模拟电路、控制、电磁、功率系统等 10 类。17 个模型总体表现低；论文报告平均结果约 19.48%–46.78%，并分析出“laziness”：模型有时只看文字、忽略图像。

怎样使用

将它用于视觉 grounding 的外部压力测试：同一题分别用原图、裁剪/清晰图、无图问题提示做对照，观察模型有没有引用真实图中节点和值。它可帮助评估多模态模型是否认真看图，但因题域更广、许多问题是基础电路题，不能替代 transistor-level AMS benchmark。

许可冲突需谨慎

Hugging Face 目前标注 MIT；论文正文同时写明 benchmark “仅限学术研究”并严格禁止商业使用。两者范围冲突。商业或再分发前应按更严格声明暂停使用并联系作者澄清。转发清单提供数据页，没有给官方评测代码仓库链接。

10AMSnet-KG — 知识图谱 RAG 与规格驱动拓扑生成把架构描述、pin 功能和专家提示作为可检索的关系网络。知识图谱前向设计仿真 / BO 闭环›

原理

图谱里一条电路带网表、全局架构/性能描述（如 cascode current mirror、高差模增益），以及局部 pin 功能/设计洞见（如器件参数配比、工作点约束）。LLM 先把规格整理成架构和关系查询，再从图谱检索子电路与 testbench、装成完整拓扑；接着以局部注释约束 Bayesian Optimization 做器件 sizing，Spectre 结果未达规格时重新生成架构。案例基于 SMIC 28 nm，仿真预算上限 2,000 次。

对两个目标的不同价值

analog-agents：思路适合增强 librarian / analog-wiki：把案例、拓扑、pin 角色、性能和验证条件关联起来，检索后由 architect 判断是否适用。analog-recovery：只能作历史背景搜索；固定 DUT 禁止套用 sizing/BO/拓扑再生成流程。图谱条目需要证据来源和置信状态，不能因为“图谱里有边”就视作当前网表事实。

资源边界

原论文说数据将在发表后公开；转发清单给的 URL 指向 AMSNet 基础资源，并非完整的 AMSnet-KG 图谱/AMSgen 代码包——不应把二者混作同一个交付。论文许可证 CC BY-NC-SA 4.0 是论文页显示的条款，单独数据权利仍须核查。

11EEschematic — 从 SPICE 网表生成可读、可编辑原理图解决网表虽可仿真、工程师却难快速审阅的问题。netlist → schematicVisual CoTMIT code›

原理

输入是 SPICE netlist，不是待识别的原理图。LLM 先识别电路子结构并用六个模拟子结构案例作少样本参考，决定模块相对位置、方向和初始布局；规则式 wiring 根据 pin/netname 接起来；视觉链式推理循环检查布线和版面，再返回人可编辑的 JSON-like schematic。论文展示 inverter、5T OTA 和 telescopic cascode amplifier。

怎样使用

对 analog-agents，可把已验证子块网表转成工程师易读的 schematic preview，辅助 librarian 检索和 architect review。对 recovery，可把已经接受的 DUT netlist 转成图形附图，报告中标明“由网表派生的视图”并保留网表哈希。不能把生成图再当成原始设计证据，也不能靠视觉美观判断连接对错。

状态

GitHub 公布 MIT 代码；论文目前用少量代表电路展示质量，适合作为用户界面/文档展示探索，不是通用 Virtuoso 原理图编辑器替代品。

12AnalogMaster — 从电路图片到版图的端到端框架把图像解读、器件尺寸搜索、placement 和 routing 放进同一闭环。image → layoutBO / SA / A*代码完善中›

原理

图像预处理使用 YOLO、OCR 和电连接分析；多个不同视觉表示分支分别提出电路结构假设，再由联合推理模块选择并形成网表。器件尺寸搜索 agent 压缩参数范围，随后用 Bayesian Optimization sizing、模拟退火 placement 和 A* routing。核心主张是联合考虑各阶段耦合，而不是把 netlist、sizing、physical design 独立优化。

结果与限制

论文在 15 张不同复杂度的代表图上评测整条流程，报告 GPT-5 Pass@1 92.9%、Pass@5 99.9%。这是论文自己的 benchmark 和方法指标，不等于可在其他 PDK/项目直接达到的成功率。GitHub README 截至 2026-09-24 仍写“代码和数据正在逐步完善”，没有成熟安装/复现说明；仓库许可证 MIT 不意味着未发布资产都已开放。

对仓库的价值

适合作为 roadmap 对照：多视图图像推理可以借来提升图像导入置信度；前向 analog-agents 可观察跨阶段参数影响。但当前仓库有角色边界、review gate、verifier 仿真、L3 PVT 和 Virtuoso 的真实工具链，不宜因论文声称端到端就让一个 agent 越过这些门禁。对 recovery 的 sizing、placement、routing 自动修改 DUT 都不适用。

建议的落地路线

先增加观测和可追溯能力，再增加自动动作。每一步都能单独验收；恢复任务仍保持“固定 DUT”。

阶段 A · 建基线与回归集

挑 CIRCUIT 的模板组、AMSbench 的 perception/analysis/design 子集和 MMCircuitEval 的 analog frontend/spec 题，建立提示版本、模型版本、输入来源、reference、评分规则和错误标签。将图像识别、拓扑、数值、推理、输出 schema 分开统计。不要把公开题当隐藏测试集，也不要把开卷训练集准确率当通用能力。

产物建议：只读 benchmark runner、版本锁定的数据清单、按技能/能力/失败类型导出的报告。

阶段 B · 案例检索增强

将现有 wiki 案例索引扩展为“模块功能—拓扑—pin 角色—规格条件—仿真来源—版次”的检索元数据。先用结构化过滤 + 文本检索做轻量 baseline；AnalogRetriever 发布源码且许可澄清后，再评估嵌入检索。每次检索结果要能指出原文、工艺、条件、日期和相似点/差异点。

注意：论文和旧案例是上下文，不是当次 circuit evidence；相似拓扑也不代表尺寸或目标指标可迁移。

阶段 C · recovery 可选图像导入

允许输入 schematic image 时，生成 sidecar：原图哈希、源页/裁剪、模型和权重版本、器件列表、每根网段的坐标与置信度、pin/net 候选、不确定交叉点及人工修改记录。转成候选 SPICE 后进入现有静态 parser、层级作用域检查、器件端序和夹具门禁。候选未被人工/独立工程复核接受前，不绑定新仿真 fixture、不写证据包。

恢复原则：解析出的 candidate 是 INFERRED / UNKNOWN；通过源图核对后才按实际证据类型提升。任何仿真都读取不可变 DUT 副本，保留尝试和失败记录。

阶段 D · 可读图形输出

对确定性解析并冻结哈希的网表，用 EEschematic 类工具生成展示图，交给 analyst/reviewer 比对网名、器件端和层级。报告的图片或图注必须经过最终审阅；如果图与网表不一致，回到源证据修正图，不让写作者自行补电气解释。

最小可行范围：先做只读的 netlist-to-preview；暂不开放 Virtuoso 写入和自动布局/路由。
明确不建议：用 benchmark 分数给某个模型贴“懂模拟电路”标签；从文本/RAG 检索命中就复制尺寸、指标或因果解释；用仿真器通过来证明图像识别正确；在 recovery 里调用规格驱动 sizing 或优化。
