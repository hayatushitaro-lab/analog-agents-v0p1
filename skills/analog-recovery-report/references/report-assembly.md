# 固定模板的实际装配（v0.10）

本卡由 REPORTER 在写 content.json 前读取。目的：一次写好工程内容，让工具负责重复结构；不增加一套人工审计附件。

## 一张验证清单驱动三处内容

`verification` 每项是一项实际测试（如电源电流、启动、负载调整率、稳定性），生成 1.6 的一行；有结果的项目在 1.8 生成子节，N且无图的项目在末尾集中展示缺口。一个 STB 测试可以对应 PM、UGF 两项指标；不能把 DC、AC、瞬态合成一行“前仿”。

```json
{
  "id": "startup",
  "category": "性能指标前仿",
  "title": "上电启动",
  "status": "N",
  "description": "计划验证上电过程；尚无有效瞬态结果",
  "metric_refs": ["startup_time"],
  "refs": ["startup_gap"],
  "labels": {
    "仿真工具": "尚未运行",
    "仿真路径": "尚无运行目录",
    "仿真方法": "先明确供电斜率、偏置、负载及建立阈值",
    "结果分析": "未验证，不能推断无过冲或启动时间"
  },
  "figures": []
}
```

以上是结构示例，ID 必须换成证据包中真实声明的 ID。status 仅 Y/N：Y 表示该行声明的验证范围已执行且结果有效，不代表性能达标；部分完成使用 N，并在说明写清已完成与未完成部分。若拆出已完成子范围，可单独一行 Y。不因缺覆盖删除行。

- 1.3 的每个 metric_ref 必须出现在对应测试的 metric_refs 中；功能测试可以没有数值指标。
- 不手写 1.6 rows。生成器复用原模板四列表格，自动填写类别、验证内容、Y/N、说明；旧 rows 只有与自动结果一致才接受。
- 1.8 不设置顶层 figures；每张验证图放入其 verification 项的 figures。工具自动放在该子节的方法之后、结果分析之前。四个固定标签无编号。
- kind=simulation 只用于实际模拟器数据，analytical 用于解析计算，concept 用于概念时序/机理，connectivity 用于实际连接。理论曲线即使合理也不能标实测。
- 旧 content.json 必须在新目录补齐上述字段，不改历史包。禁止绕过校验或修改填充器临时出报告。

## 各章节的最小工程任务

| 章节 | 写作动作 | 不接受的替代物 |
|---|---|---|
| 1.3 | 电源/温度条件行；各指标定义、可比采样极值、典型条件；单点数值仍显示 | 将单点温度写成全温范围；为了填表任挑 typ；不同频率/负载区间混成 PVT 极值 |
| 1.4.1 | 相同方向/状态相邻，说明一句话优先；来源、去向、极性必要时补充 | 扇出栏填“偏置输入”等角色；长段机理塞接口表 |
| 1.4.2 | 有控制/启动顺序时给时序图；没有实测则画不含虚构延迟的概念时序 | 只写“见仿真”；用理想曲线冒充波形 |
| 1.5 | 基础物理/反馈机制→本电路分块与图→收益、代价和适用条件 | 只有器件列表；只有通用教科书；只有取证流程 |
| 1.7.1 | 沿实际路径解释扰动如何传到输出、反馈如何纠正；给关键尺寸比、OP与适用方程 | 无依据 gm/增益/寄生值；结构像某电路就断言工作区 |
| 1.7.2 | 一种实际 model 一行，型号名称在首列；描述极性/类别、已知额定域、可获取的方阻/电容密度及来源 | 同一个型号按实例重复；实例尺寸代替型号属性；猜 PDK 数字 |
| 1.7.3 | 分清已观测异常和潜在风险，写触发因素、影响和验证动作 | 凑条数；因未见独立模块就断言完全没有保护 |
| 1.8 | 每测试：条件与量的定义→图→典型/极值解释→覆盖边界 | 图片堆在章首；以历史回放/静态审计作为全部性能测试 |
| 1.10 | 据前端证据给大电流路径、高阻敏感点、匹配、耦合、屏蔽/隔离建议 | 没有版图所以整节不分析；哈希替代布线要求；虚构线宽/电阻限值 |

1.7.2 未知器件属性只将该属性写未确认；已有型号、类别仍列出。不同 section 的同名型号差异写在同一行说明，不能静默拼成一个已确认模型。实例尺寸归 1.7.1。没有版图只限制“已实现”的结论，不阻止前端提出有依据的布局建议。

## 指标缺数的处理

先回证据包查询原始采样：有数值但没有 typical_case_id，应补充典型条件的工程选择及依据，或写“未指定典型工况”，不写“未测”。不能在报告生成时偷偷选择。无预定义典型条件的旧结果可以后选一个可复核参考工况，但要注明是本次表征选择、非原始规格。未指定typ的单个结果由填充器在参数说明列显著显示；SIMULATED标单工况，DERIVED标单个派生结果，不从一个标量推断原始采样只有一点。扫描到的最大负载仅是已验证至该点，不自动成为最大能力或典型值。

## 最终复核

填充时使用 `compact_metrics: true`，共同条件明确列在1.3表前。工具对每行精确相同的条件去重，保留不同工况，并将基础V/A/W/s按该指标量级整体换算为工程单位；其他单位保持原样。完整case ID与条件保存在bound-content及trace中，原始值留证据包。不要用小字体补救重复文字，也不要删掉差异条件换取短表。

可见页脚中的总页数必须保持原生NUMPAGES字段，不能用隐藏/锁定字段替代。渲染失败保留草稿并报告实际错误，不擅自把失败归因为永久引擎损坏。

先看读者能否跟随电路，再按 1.3→1.6→1.8 核对；特别抽查正文和图注中**证据表之外新增的数字**。每项仿真结论回到原数据和真实夹具。哈希、case ID 全表及过程日志留 sidecar；正文只保留读者需要的条件、运行路径和结论。自动校验只能发现结构问题，不能承诺自然语言正确。


## 已确认的器件与验证图约定（2026-09-22）

1.7.2仅列实际器件型号及有依据的属性，不列逻辑子电路/功能模块；后者放1.5或1.7.1。注意PDK器件也可能由subckt封装，按实际器件语义区分，不能仅凭subckt语法排除。

1.8每个已完成仿真的子节必须有对应真实结果图，并绑定本节工况、原始数据及运行编号。标量结果可画实际扫描点、对比图或工作点注释图，不伪造连续曲线；不得放无关图凑数。N且无图的项目由生成器在1.8末尾集中列出，保留1.6全部行；原工具/路径/方法/结果字段留在trace，不丢证据。部分完成项展示已有图并写清边界，不以伪图或删除验证清单绕过。
