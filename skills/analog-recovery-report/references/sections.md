# 模板章节契约：模拟模块设计说明书

适用于当前 1.1～1.13 模板族。每次核对用户提供的模板蓝字；编号相同不代表要求相同。
来源：本项目通用模板指导提炼，附加已确认的工程阅读规则。以下不是项目原始规格。
首要覆盖：当前用户授权和例外优先。反向重建中，原始指标/原作者意图可能无法恢复，不能为了填满模板补造。

## 1.1 功能

复用模板的原生星形项目符号、字体和缩进，不能手敲ASCII星号代替；分段说明模块用途、服务对象和系统位置。系统需求有来源才当事实，否则说明当前结构支持的功能推断。
每项功能向后关联特性、指标或验证；正文先讲电路而非取证流程。

## 1.2 特性

星号分段给主要特性和成立条件，说明性能之间的取舍。无原始优先级时做当前工程分析，不能冒充历史设计决策。

## 1.3 指标

第一行组先保留工作条件：`condition_rows` 必须各有一行 `quantity=supply_voltage` 和 `quantity=temperature`，每行 8 个 `cells`、`refs` 与 `source_kind`；未知值也保留为 `UNKNOWN`。再列主要/次要需求分组和符号、说明、条件、min/typ/max、单位。

保留工作条件、主要/次要需求分组和符号、说明、条件、min/typ/max、单位。
原始要求与实际表征分清；没有原始规格时标“表征”，不写通过。样本极值直接放此表，不藏到验证章。
条件含模式、模型/角、供电、温度、负载等；typ 使用预定义工况，不用平均值代替。`source_kind` 使用证据层枚举 `DIRECT`、`DERIVED`、`SIMULATED`、`INFERRED`、`UNKNOWN`。供电和温度条件不是性能 metric，不设置 `metric_ref`，避免把用户条件伪装成 DERIVED 结果。缺任一条件行时应明确报错；v0.4 内容升级时补两行 UNKNOWN 即可。
相同首列分组可合并。各模式分别填写；适用且相同的工作条件一致呈现，性能结果不得互相复制。
只有典型/部分范围/未测时，列出缺失原因及下一步；不把单点当范围。能力边界定义判据，区别产品保证。
面积在没有版图时未知，不按器件尺寸假造；本项目 SArea 保留 μm² 单位、数值可空。

## 1.4 接口定义

1.4.1 按接口方向/状态分组，同组按名称排序；保留名称、状态、迟滞、扇入/扇出及说明等模板列。
方向相对所报告模块判断；同名信号在上游是输出、下游是输入不矛盾。说明电源域、来源/去向、模式相关性。
扇入/扇出按模板要求用工艺反相器倍数时，缺数字库证据就写未确认，不能编造。
1.4.2 用简洁时序图或实际波形说明边沿、先后、阈值与延迟；最差角未覆盖必须写明。

## 1.5 实现方案

第一层先讲基础物理/反馈机制和系统方框图，第二层映射本模块分区，器件细节放 1.7。
方案来源、继承关系有依据才填写；可作现结构与替代方案的条件性比较，不冒充原设计者曾评估过。
每段围绕“机制→收益→代价→成立条件”，避免连续大段或纯实例枚举。

## 1.6 验证方案

列功能、前仿、后仿、Monte Carlo 类别，与指标/功能逐项映射。功能并入前仿需说明。
前仿覆盖约定主要指标矩阵；后仿重点涵盖寄生敏感项，未取得 PEX 就写未测。
适用 MC 的次数按项目要求、模型能力及统计置信度确定；模板示例不能自动成为本项目固定次数。项目暂缓时保留未完成原因，不能改成不适用。
缺 mismatch 模型是阻碍，不足以证明失配分析不适用。用户未授权统计运行时不能因模板自动超预算。
状态栏只填 Y/N；Y 表示该行范围已有有效结果，不代表达标。部分/待测填 N，在说明列写已完成部分、原因、影响和补齐条件。由 verification 清单自动生成原模板表格，每种测试单独一行。没有实际人员评审不伪填评审人或签字。

## 1.7 设计实现

1.7.1 分行编号解释信号/电流路径、反馈、启动、偏置、控制和关键权衡；器件表包含所属分区及作用。
W/L/m/nf、面积比和电阻比来自静态证据；实际电流、gm、工作区来自模型语义已确认的工作点，不凭拓扑断定全部饱和。
1.7.2 按 model 名称去重，保持型号名称/器件描述两列。描述类别、极性、已知电压域和可获取的方阻/电容密度；属性要有模型 metadata 或 PDK 依据，缺失就注明。不同实例的 W/L/m/nf 属于 1.7.1，不能代替型号属性。
1.7.3 风险按“触发因素→可能现象→影响→验证”列出，区别已观测异常与潜在风险。

## 1.8 设计验证

有结果的子节按当前模块的实际验证内容命名，具备仿真工具、仿真路径/运行号、方法/条件、结果分析。未完成项按装配工作卡在末尾集中展示，保留原因、影响和下一步。
“仿真工具、仿真路径、仿真方法、结果分析”四类固定标签前不加编号，保持模板原样；其他长说明可分层编号，每项独立成段。语义间用段间距留白。
图表要解释，不能只贴波形。数字同源于 1.3，所称 min/max 与扫描集合一致。
验证图必须放在对应 verification 项的 figures 内，不能集中放在 1.8 章首。理论计算图使用 analytical 标注，不能标成实际仿真数据。
静态、动态、独立夹具、集成、前仿和后仿分别呈现；失败结果和模型限制保留。
适用 MC 统计列 min/max/mean/sigma/均值±2sigma/±3sigma 及极值样本编号；统计区间不自动等于保证区间。
用层级和编号组织；列宽适配内容，数字和单位不要断成无意义片段。完整哈希放证据附件。

## 1.9 脚本检查

保留 RUNPERC 清单、命令/工具规则版本和检查状态；有日志才能写执行/通过。模板 Y/N 和示例路径不是证据。
规则或工具缺失写未执行及原因，不把模板命令作为实际执行记录。

## 1.10 后端说明

1.10.1 分组列电源域、高阻/高压节点、大电流路径、最大电流和关键耦合；量值注明工况。
1.10.2 特殊要求—物理实现逐项对应；匹配/屏蔽/隔离建议标为建议，不能填成已实现版图。
模板示例阈值不是项目限值；“见线路图”必须有可定位的图。后端未确认的实施列保留待填。

## 1.11 ECO 策略

说明 option 的目的、更改方法、效果及物理实现。trim 有可调性不代表已证实 NVM/熔丝/FIB 路径。
区分已存在的调整机制与建议候选，后端动作未知不硬填。

## 1.12 / 1.13 物理实现与物理验证

后端负责实际布局/面积/线宽及验证工具、规则、日志与结果。没有当前项目资料时写待后端补充；只有当前项目明确约定才保留标题为空，不继承历史项目的例外授权。
不能根据 schematic 或模板默认状态声称 DRC/LVS/PERC 通过。

## 终审

# 1.8 四个固定标签的语义检查

标签正确不等于内容正确。写完后逐项核对：

- 仿真工具：实际模拟器版本、模型版本和实际角组合。
- 仿真路径：可定位的运行目录、运行ID、原始日志和数据位置。不能把夹具条件填进这一栏。
- 仿真方法：供电、温度集合、控制/trim、负载、求解辅助、量的定义与提取公式。
- 结果分析：典型值与采样极值及其工况、曲线解释、与电路分析的关系、未覆盖范围。箱式TC使用集合最大最小值，不称为“两个温度端点之差”，除非极值确实落在端点。

更新结果后联动检查1.3指标表、1.4接口说明、1.6验证状态、1.7分析和1.8，不保留“未运行/未供电”等已失效措辞。保留条件和性能两类行，不能为了缩短指标表删掉供电/温度。
