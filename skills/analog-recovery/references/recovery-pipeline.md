# recovery 编排：固定电路分析循环

本流程借鉴analog-agents编排、wiki及evolve，保留其仓库结构，不调用正向设计/调参循环。输入是既有实现，不凭工艺/拓扑补原始规格。

## 中央调度与阶段

主代理建立输入/条件记录、章节需求和任务表，决定下一步并合并证据；只有主代理派子代理和分配预算。按[角色工作卡](role-cards.md)提供对应技能段落和局部材料，不向每个代理发送全部 references。

先按 [effort.md](effort.md)准备本次workflow/site，角色任务附 resolved.role_policy 对应部分与资源，不另套正向默认规格或effort规则。主代理按execution/review_transport实际推进，配置阻断与用户明确禁用分别记录。派发后记录 agent_id、task_id、时间和实际读取技能；验收记录 complete/partial/blocked 与原因。回放使用原始数据重算，禁止把已有结果的摘要复制当作本轮执行证据。主代理可以复用历史报告更新未变章节，但必须记录继承范围，不能据此声称全新生成或独立泛化。

小模块默认主代理做 ANALYST，子代理做独立 REVIEWER；需要持续运行/后处理时另派 VERIFIER。简单单次执行可由主代理承担验证角色。大模块由主代理担任 ARCHITECT，按真实接口分派各子块 ANALYST；共享环路/互偏置组织联合任务，不能按文件机械拆分。EDITOR 在证据冻结后工作，可由主代理承担。子代理不自行扩张团队。

| 阶段 / owner | 必需交接 | 失败路由 |
|---|---|---|
| S0 准入 / 主代理 | 路径、条件来源、章节需求、工具与预算 | 缺项具体到条件/文件；继续不依赖它的任务 |
| S1 分块 / ARCHITECT，大模块才用 | 实际接口、共享依赖、子块任务 | 未解层级限制相关边界；局部分析继续 |
| S2 理解与计划 / ANALYST | 因果链、方程前提、竞争解释、端口/模式、测量计划、夹具版本 | 补源事实，不用典型拓扑补数值 |
| S3 预审 / REVIEWER 与 VERIFIER | 独立原理复核、驱动/负载/计量审查 | 原理或夹具回 ANALYST，缺产品条件交主代理 |
| S4 执行 / VERIFIER | 原日志/数据、退出码、条件化测量、异常 | 执行/后处理自身修复；夹具改版后重新预审 |
| S5 解释更新、集成 / ANALYST、ARCHITECT；REVIEWER 核验 | 支持/冲突、覆盖；独立夹具和真实顶层差异 | 仅重开受影响问题，不重新跑全流程 |
| S6 冻结与写作 / 主代理、EDITOR | 按[覆盖与停止检查](coverage-closeout.md)决定继续或冻结；证据包、真实章节映射、报告、同源预览 | 可执行的主要缺口回 S2/S4；排版留 EDITOR |
| S7 案例归档与复盘 / 主代理 | standard及以上执行 analog-evolve recovery 分支，再准备同库案例和知识差异；记录实际执行/批准/应用/读回状态 | partial 也可复盘；未执行不得记作技能已执行，未归档不得记作已归档 |

纯静态任务的 S3 只需 REVIEWER；有实际夹具或待运行计划时才加入 VERIFIER 预审。纯静态任务可跳过 S4，交付明确未测内容；局部缺证不阻断其他章节。技术错误先修正或撤回，不能仅加限定词通过。文件检查通过不证明原理或自然语言正确。

需要且允许委派时使用当前原生协作工具，模型和推理档位服从任务选择；未指定则继承。需要覆盖模型时提供自包含任务包。无可用子代理时串行完成并记录独立复核缺失。

远程时间/并发由主代理分配，失败尝试也计入总预算，不能每个子代理各领取全部额度。超时只表示状态未明，先看任务进度与产物，不重复提交。所有派发应有可以独立执行的具体任务，主代理同时推进其他有用工作。

## 分析任务与循环

1. 从模板和静态IR产生当前电路的问题清单：模式控制、参考/偏置来源、反馈符号、关键尺寸比例、适用指标。每题对应实例范围与影响章节，不预填答案。
2. 取证者每次完成一个局部任务：连接事实→有条件的因果/方程→反例→最小补证；使用evidence的作用域连接工具。未知模型不能阻断已确定的连线或电阻支路算术。
3. 按 [外部评审循环](external-review.md)使用已配置第三方 API 复核原始局部包、假设及结果；REVIEWER 角色组织调用与路由，不冒充外部模型。未配置/不可用时明确记录外部复核缺失；不静默改成同模型评审并称为跨模型。检查跨层级绑定、符号链、计量面、适用范围，发现问题自动退回责任角色并带证据复审。
4. 异常需要区别“未做”“无法做”“数据与假设冲突”。选择一项能区分竞争解释的诊断，在授权预算内执行，记录观察如何改变认识。不能只添加qualified后停止。
5. 报告前逐内容项验收：作用、具体信号路径、关键比例、条件性收益/代价。缺少其中内容可部分交付，但不得标complete。文件校验通过不能代替此验收。

若复核者不可用，先检查实际子代理工具；记录不可用原因，不伪造独立审阅。模型设置继承任务选择；局部小任务不扩张团队，用户明确要求单代理时遵从。

## 与现有仓库连接

仓库路径从当前项目配置或用户提供值读取，不从skill所在目录推测根目录。共享绑定放`skills/analog-recovery/_local/site.json`，字段见`site.example.json`；本轮workflow引用准备器生成的run/site.json。project_root是工作区证据根，run_dir是本任务输出与额度账本根，不再绑定某个历史测试WORK。原复制仓库和安装目录不是维护源。

借用analog-learn的信号路径/物理解释、analog-audit的检查方法和analog-verify的夹具复核；读取相应技能的适用部分。表征范围由本项目决定，不采用默认供电、N=8、默认温漂、原规格或全角通过要求。

wiki检索及evolve候选按evidence的[仓库适配](../../analog-recovery-evidence/references/repository-adapter.md)。已有案例是参考，不是当前电路事实。不要调用archive-project把未知或部分取证归档成设计收敛。

## 项目轨迹

在本次run保存追加式`recovery-iterations.jsonl`，每项写：question_id、iteration、before（假设）、action、evidence_refs、after（更新）、remaining、next_action、stop_reason。

支持/反驳/无法区分都是有效结果；没有新证据不能称认识提升。局部两轮不同诊断仍无进展时总结当前可支持范围，再根据剩余预算与价值选择继续或降级；不重复相同动作耗尽资源。

收尾加载本仓库 analog-evolve 的[recovery 分支](../../analog-evolve/references/recovery.md)，消费原生轨迹，不交给正向参数演化引擎。之后按 evidence 的仓库适配更新同一项目案例，使用原 wiki 目录、type/content/derived_from/confidence 与关系文件。已有相应写回授权时，在本 run 准备并审查差异后应用；只读任务只准备候选。局部修订保留旧说法及出处，缺独立复核时保持 unverified/partial。报告完成不改变设计收敛状态。
