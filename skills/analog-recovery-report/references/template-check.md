# 模板写作与确定性检查

从当前模板提取约定，不能把某份模板的符号、章节序号或段落索引硬编码成所有报告规则。

- 项目符号复用模板的Word原生编号定义、实际符号字体、级别及缩进；手敲`*`不是等价实现。相同视觉符号可有不同numId，不靠ID相同判断一致。
- 同一编号一段，长段按语义拆分；用适量段间距留白，避免堆空段造成分页问题。固定模板标签不参与自编编号。
- 当前中文模板族的1.8固定标签“仿真工具、仿真路径、仿真方法、结果分析”前不加编号。其他说明可分层编号。别的模板先提取其标签约定。
- 先讲基础原理，再映射实际结构及关键器件功能分区；假设保留条件，不能写成原设计意图。
- 接口按状态分组、组内排序；同义类别可合并，跨页仍需可辨识。列宽随内容调整，不能靠缩小到难读的字号容纳文字。
- 工作条件的计划范围和已测性能覆盖分开。补全计划min/typ/max不能顺便补造性能min/max。

## 可配置Word检查

生成本任务`template_profile.json`，从模板中选一个真实项目符号示例段落，并选报告正文的精确起止标题。配置只读取正文直接段落，不用于表内标题或无法区分的重复模块标题；重复范围先拆成单模块检查，不静默猜索引。

```json
{
 "bullet_sections":[{"start":"功能","end":"指标","skip":["特性"],"template_example":"功能1","template_occurrence":0}],
 "label_sections":[{"start":"设计验证","end":"脚本检查","labels":["仿真工具","仿真路径","仿真方法","结果分析"]}]
}
```

以上仅是当前模板族示例，不是通用默认值。对应字段必须存在，找不到标题/示例要报错，不应跳过后给pass。
模板存在重复示例时，显式指定从0开始的template_occurrence（本例选第一模块）；未指定时拒绝歧义。

`python scripts/check_docx.py template.docx report.docx template_profile.json`

脚本标准库运行、不改文件。它解析实际编号符号/字体，检查固定标签前手写或原生编号；不检查完整样式继承、缩进、表格美观、所有图文数字或语义质量。这些继续通过模板比较、证据校验及实际渲染审阅。

输出新版本名，避免与用户已打开的同名Word文档冲突；保留原版。Word导出后检查文件确实存在且页眉、图片已经加载。自动化失败只处理本任务创建的进程，不能关闭用户已有文档。必要时单文档重新导出，再逐页查看。
